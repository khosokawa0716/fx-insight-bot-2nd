# 特徴量リファレンス

`build_features()` が生成する各列の意味・計算式・サンプル算出例。

---

## 元データ（tick）

取引所から届く約定の生データ。1行 = 1約定。

| 列 | 意味 |
|---|---|
| `timestamp` | 約定日時 |
| `side` | `BUY`（買い） or `SELL`（売り） |
| `size` | 約定数量（BTC） |
| `price` | 約定価格（円） |

```
timestamp                   side    size    price
2025-11-30 21:00:01.694    BUY     0.0014  14305210
2025-11-30 21:00:01.732    BUY     0.0002  14305210
2025-11-30 21:00:15.242    SELL    0.0017  14302155
2025-11-30 21:00:59.000    BUY     0.0010  14305320
```

これを1分単位で集計したものが以下の特徴量。

---

## OHLCV

> Open / High / Low / Close / Volume（始値・高値・安値・終値・出来高）

ローソク足の基本要素。1分間の価格の動きをまとめたもの。

| 列 | 意味 | 算出方法 |
|---|---|---|
| `open` | 始値 | 分足内の**最初**の約定価格 |
| `high` | 高値 | 分足内の**最大**約定価格 |
| `low` | 安値 | 分足内の**最小**約定価格 |
| `close` | 終値 | 分足内の**最後**の約定価格 |
| `volume` | 出来高 | 分足内の size 合計 |

### サンプル算出（21:00）

```
open   = 14305210  ← 21:00:01 の最初の tick
high   = 14305320  ← 4本の中の最大値
low    = 14302155  ← 4本の中の最小値
close  = 14305320  ← 21:00:59 の最後の tick
volume = 0.0014 + 0.0002 + 0.0017 + 0.0010 = 0.0043
```

---

## VWAP

> Volume Weighted Average Price（出来高加重平均価格）

単純平均と違い、**大きな取引ほど価格への影響が大きい**平均価格。
「この1分間、実質いくらで取引されたか」を表す。

```
VWAP = Σ(price × size) / Σ(size)
```

### サンプル算出（21:00、先頭3tick）

```
分子 = 14305210×0.0014 + 14305210×0.0002 + 14302155×0.0017
     = 20027.29 + 2861.04 + 24313.66
     = 47202.0

分母 = 0.0014 + 0.0002 + 0.0017 = 0.0033

VWAP = 47202.0 / 0.0033 ≈ 14303636.2
```

安値（14302155）で大きな売りがあったため、単純平均（≈14304192）より低い値になる。

---

## Imbalance（買い圧力比率）

> Order Flow Imbalance

BUY と SELL のどちらが優勢かを 0〜1 で表す指標。
0.5 で均衡、1.0 に近いほど買い圧力が強い。

```
Imbalance = BUY の size 合計 / 全体の size 合計
```

BUY が 1 本もない場合は `0.0` になる。

### サンプル算出（21:00、先頭3tick）

```
buy_volume  = 0.0014 + 0.0002 = 0.0016  （BUY の tick のみ）
total_volume = 0.0033

Imbalance = 0.0016 / 0.0033 ≈ 0.4848
```

0.5 を下回っているので、この1分間はやや売り優勢。

## Shannon Entropy（取引分布の乱雑さ）

> Shannon Entropy of Trade Sizes

1分間の約定が「一部の大口に偏っているか、細かく分散しているか」を数値化した指標。

- **値が小さい（0 に近い）** → 1〜2件の大きな取引が1分間を支配している（大口プレイヤーの動き）
- **値が大きい** → 多数の小口取引が細かく積み重なっている（多様な参加者）

### 直感的なイメージ

1分間に取引が 3 件あったとして：

```
パターンA（偏り大）: 98% + 1% + 1%  → entropy が低い ≈ 大口1件が支配
パターンB（均等）:  33% + 33% + 34% → entropy が高い ≈ 細かく分散
```

「次の tick はどんなサイズか予測しやすいか」が低いほど entropy が高い、というイメージ。

### 計算の手順

**① 各 tick の「占有率」を求める（p）**

```
p_i = この tick の size / 分足の size 合計
```

**② 各 tick の「驚き度」を求める（-log2(p)）**

`-log2(p)` は「珍しさ」の指標。占有率が低い（小さな取引）ほど値が大きくなる。

```
p = 0.50 → -log2(0.50) = 1.0   （2件に1件の頻度、普通）
p = 0.25 → -log2(0.25) = 2.0   （4件に1件、やや珍しい）
p = 0.06 → -log2(0.06) ≈ 4.0   （17件に1件、かなり珍しい）
```

**③ 「占有率 × 驚き度」の合計が Entropy**

```
Entropy = Σ(p_i × (-log2(p_i)))
        = -(p1×log2(p1) + p2×log2(p2) + ...)
```

大きな取引（p が高い）は「驚き度」が低いので貢献が小さく、
小さな取引（p が低い）は「驚き度」が高いがそもそも少ないので貢献が大きくなりすぎない。
この性質により、**最もバランスよく均等なときに entropy が最大**になる。

### サンプル算出（21:00、先頭3tick）

```
total = 0.0033

① 占有率を計算
   p1 = 0.0014 / 0.0033 ≈ 0.4242  （BUY 1本目、約42%）
   p2 = 0.0002 / 0.0033 ≈ 0.0606  （BUY 2本目、約6%）
   p3 = 0.0017 / 0.0033 ≈ 0.5152  （SELL、約52%）

② 各 tick の「p × (-log2(p))」を計算
   p1 の項: 0.4242 × (-log2(0.4242)) = 0.4242 × 1.2370 ≈ 0.5247
   p2 の項: 0.0606 × (-log2(0.0606)) = 0.0606 × 4.0444 ≈ 0.2451
   p3 の項: 0.5152 × (-log2(0.5152)) = 0.5152 × 0.9564 ≈ 0.4927

③ 合計
   Entropy = 0.5247 + 0.2451 + 0.4927 ≈ 1.2629 bits
```

p2（BUY 2本目、6%）は小さい取引なのに「驚き度」が高く（4.0）、
合計への貢献が意外と大きい（0.2451）ことがわかる。

### 値の範囲

| 状況 | Entropy |
|---|---|
| tick が 1 本のみ | `0.0`（不確実性なし） |
| 3件（サンプル） | `≈ 1.26 bits` |
| 4件すべて均等 | `2.0 bits`（= log2(4)） |
| N件すべて均等 | `log2(N) bits`（理論上の最大値） |

## まとめ

| 特徴量 | 値の範囲 | 何を見るか |
|---|---|---|
| `open/close` | 価格（円） | 分足の始まり・終わり |
| `high/low` | 価格（円） | 分足内の値幅 |
| `volume` | 数量（BTC） | 取引の活発さ |
| `vwap` | 価格（円） | 実質的な取引価格 |
| `imbalance` | 0.0 〜 1.0 | 買い/売りの圧力バランス |
| `entropy` | 0.0 〜 log2(N) bits | 取引の多様性・集中度 |
