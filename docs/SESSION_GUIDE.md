# セッション運用ガイド

Claude Code とのセッションを効率よく進めるための手順書。

---

## セッション開始時

### 1. 現在地の確認

Claude に以下を確認してもらう：

- 「前回の続きから始めたいです」
- 「メモリと TODO.md を確認して状況を教えてください」

Claude は自動的に以下を確認する：
- `memory/` の記録（前回の合意・判断）
- `docs/TODO.md`（現在フェーズとタスク）
- `git branch`（現在のブランチ）

### 2. ブランチの確認

作業ブランチがなければ Claude に作ってもらう：

```
新しいブランチを作ってください
```

---

## セッション終了時

### やること（Claude に頼む）

```
今日はここまでにしたいです。まとめとTODO.mdの更新をお願いします
```

Claude は以下を行う：

1. **メモリの更新** — 今日の合意・判断・判明事項を `memory/` に保存
2. **TODO.md の更新** — 完了タスクにチェック・新タスクを追記
3. **コミット** — `/commit` スキルで変更を記録
4. **次のブランチ作成** — 次セッションの作業ブランチを用意
5. **PRの作成（任意）** — `main` へマージしたいときは `/pr` スキルを使う

---

## ブランチ運用

### 命名規則

```
feature/<作業内容>_<日付8桁>

例:
  feature/eda_20260522
  feature/api-verification_20260607
  feature/backtest_20260610
```

### 作成タイミング

- セッション開始時（新しい作業を始めるとき）
- セッション終了時（次回の作業ブランチを先に作っておく）

### マージの手順

1. Claude に `/pr` でプルリクエストを作ってもらう
2. GitHub でマージする
3. `main` ブランチに切り替える

---

## よく使うスキル

| やりたいこと | コマンド |
|------------|---------|
| コミットを作る | `/commit` |
| PRを作る | `/pr` |
| コードレビューしてもらう | `/code-review` |

---

## メモリについて

Claude は `memory/` フォルダに以下を記録している：

| ファイル | 内容 |
|---------|------|
| `project_eda_plan.md` | EDA 検証結果と知見 |
| `project_phase2_plan.md` | Phase 2 の方針・合意事項・API仕様 |
| `project_test_reference.md` | テスト用サンプル値 |
| `feedback_review_patterns.md` | レビューで学んだコードパターン |

長いセッションでは文脈が圧縮されることがある。重要な決定をしたら「メモリに残してください」と一言添えると確実。
